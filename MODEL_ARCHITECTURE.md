# Pangenomic GAT: Model Architecture

A multimodal graph neural network for predicting gene regulation by fusing 3D chromatin structure, DNA sequence, and epigenomic signals.

---

## Overview

The **Pangenomic GAT** is a **two-tower (or three-tower) deep learning architecture** that predicts gene regulatory activity by integrating:

1. **3D Chromatin Structure** — PCHi-C promoter-enhancer interactions forming graph topology
2. **DNA Sequence** — Promoter region sequences (±1–16 kb around TSS)
3. **Epigenomic Signals** — Histone modification marks (H3K27ac, H3K4me1, CTCF, etc.)

The model outputs **four predictions** per (gene, tissue) pair:
- **Link strength** — Does this promoter-enhancer pair interact?
- **Expression level** — Is the gene expressed in this tissue?
- **Tissue-specificity** — Is the gene restricted to few tissues?
- **Tissue identity** — Which tissue is this sample from?

---

## Architectural Backbone

### High-Level Structure

```
Input: (Gene, Tissue) pair
    │
    ├─→ Tower 1: DNA Sequence         → z_seq (128-dim)
    ├─→ Tower 2: Structure + Histones → z_struct (128-dim)
    └─→ [Tower 3: Histones only]      → z_epi (128-dim)  [trimodal only]
          │
          ↓
    Fusion Layer → z_fused (128-dim)
          │
          ↓
    ┌─────────┴─────────┬─────────┬─────────┐
    ↓                   ↓         ↓         ↓
  Head 1              Head 2    Head 3    Head 4
  Link Pred.          Expr.     Tau       Tissue
  (Binary)            (Binary)  (Binary)  (46-class)
```

## Tower 1: Sequence Encoder (HyenaDNA-Style)

### Purpose
Captures **regulatory motifs and patterns** in promoter DNA sequences using long-range convolutions.

### Input
- **Promoter sequence:** ±8 kb (or ±500 kb in 1Mb variant) centered on canonical TSS
- **Encoding:** One-hot [A, C, G, T] → shape `(L, 4)` where `L` = sequence length
- **Preprocessing:** Cached as uint8, cast to float32 per batch

### Architecture

```
Input: DNA sequence (L × 4 one-hot)
    ↓
[Stem Conv1d]
  • Kernel: 15, Stride: 4
  • Maps 4 → 128 channels
  • Reduces length: L → L/4
    ↓
[4× HyenaOperator Blocks]
  Each block:
    ├─ LayerNorm
    ├─ Implicit long-convolution (O(L log L) via FFT)
    │   • Filter generated by positional MLP
    │   • Order-2 recurrence (depth of gating)
    ├─ SwiGLU gating
    └─ Residual connection
    ↓
[Global Average Pooling]
    ↓
Output: z_seq (128-dim embedding)
```

### Key Features
- **Long-range dependencies:** HyenaOperator reaches 16 kb context in one layer (vs. log₂(L) layers for dilated CNN)
- **Reverse-complement equivariance:** `z(seq) = z(reverse_complement(seq))`
  - Model averages forward and RC embeddings
  - Enforces strand-agnostic representation
- **Computational efficiency:** O(L log L) via FFT, not O(L²) attention

### Hyperparameters
```python
hyena_d_model: 128       # Channel width
hyena_blocks: 4          # Number of operator blocks
hyena_order: 2           # Recurrence depth
hyena_filter_order: 64   # Filter MLP width
stem_kernel: 15
stem_stride: 4
```

## Tower 2: Structure + Epigenomics (Graph Attention Network)

### Purpose
Learns **3D chromatin topology patterns** that bring distal enhancers into spatial proximity with promoters.

### Input: Graph per (gene, tissue)

**Nodes:** Genomic fragments
- **Anchor node:** Bait fragment containing the gene's promoter
- **Neighbor nodes:** Top-K prey fragments by CHiCAGO score (K ≤ 10,000)

**Node Features (per fragment):**
- 7 histone marks: H3K4me1, H3K4me3, H3K27ac, H3K27me3, H3K36me3, H3K9me3, CTCF
  - Aggregated as mean signal over fragment from bigWig files
  - Missing marks → signal=0, mask=0 (masked, not imputed)
- Positional encoding (linear genome coordinate)
- Node degree (number of connections)

**Edges:** PCHi-C loops + optional backbone

**Edge Features:**
- **CHiCAGO score** — Statistical significance of interaction (≥5.0 threshold)
- **Genomic distance** — Linear bp distance between fragments
- **Hi-C contact frequency** — From Juicer .hic files (if available)
- **[Optional] Backbone edges** — Linear adjacency (GrapHi-C style)

### Architecture

```
Input: Graph G = (V, E) with node features X, edge features E_feat
    ↓
[3× GATv2 Layers]
  Each layer:
    For each node i:
      h_i^(l+1) = Σ_{j ∈ N(i)} α_ij · W^(l) h_j^(l)
    
    Where attention α_ij:
      e_ij = LeakyReLU( a^T [W h_i || W h_j || edge_features] )
      α_ij = softmax_j(e_ij)  [over neighbors j]
    
    • 4 attention heads per layer (multi-head attention)
    • 128-dim hidden per head
    • Dropout: 0.2 (node features), 0.1 (attention weights)
    ↓
[Mean Pooling]
  • Average over all nodes in subgraph
  • Produces graph-level embedding
    ↓
Output: z_struct (128-dim embedding)
```

### Key Features
- **GATv2 (not GAT):** Attention mechanism is dynamic (query-key dependent)
- **Multi-head attention:** 4 heads capture different interaction patterns
- **Handles variable-size graphs:** Different promoters have different numbers of neighbors
- **Edge-aware:** CHiCAGO/Hi-C scores inform attention weights

### Hyperparameters
```python
gat_layers: 3
gat_heads: 4
d_hidden: 128
dropout: 0.2
attn_dropout: 0.1
max_neighbours: 10000
min_chicago: 5.0
add_backbone_edges: True
```

## Tower 3: Epigenomics-Only Encoder (Trimodal Variant)

### Purpose
Provides a **pure epigenomic view** independent of graph structure (ablation study).

### Input
- Histone marks at **anchor fragment only** (7-dim vector)
- No graph topology, no neighbors

### Architecture
```
Input: 7-dim histone vector
    ↓
[EpiEncoder MLP]
  • 2-layer feedforward
  • 7 → 64 → 128
  • ReLU activation
  • Dropout: 0.2
    ↓
Output: z_epi (128-dim embedding)
```

## Fusion Layer

### Two-Tower Fusion (FiLM — Feature-wise Linear Modulation)

```python
z_fused = z_struct ⊙ γ(z_seq) + β(z_seq)
```

Where:
- `γ(z_seq)` = learned scale parameters (affine transformation)
- `β(z_seq)` = learned shift parameters
- `⊙` = element-wise multiplication

**Intuition:** Sequence modulates structure representation — DNA motifs guide how 3D contacts are interpreted.

### Three-Tower Fusion (Gated)

```python
[w_struct, w_seq, w_epi] = softmax(MLP([z_struct; z_seq; z_epi]))
z_fused = w_struct · z_struct + w_seq · z_seq + w_epi · z_epi
```

**InfoNCE Alignment Loss:**
```python
L_align = -log( exp(sim(z_struct, z_seq) / τ) / Σ_negatives )
```
- Encourages agreement between modalities on same sample
- Contrastive: pull together same sample, push apart different samples
- Temperature τ = 0.1

---

## Prediction Heads (Multi-Task Learning)

All heads take `z_fused` as input.

### Head 1: Link Prediction
```
z_fused → Linear(128 → 1) → Sigmoid → P(interaction)
```
- **Target:** CHiCAGO score ≥ threshold (binary)
- **Loss:** Binary cross-entropy + focal weighting
  - Focal loss: `(1 - p_t)^γ · BCE` (γ=2)
  - Addresses class imbalance (most pairs don't interact)

### Head 2: Expression Level
```
z_fused → Linear(128 → 1) → Sigmoid → P(expressed)
```
- **Target:** TPM ≥ 1.0 (binary)
- **Loss:** Binary cross-entropy + focal weighting

### Head 3: Tissue-Specificity (Tau)
```
z_fused → Linear(128 → 1) → Sigmoid → P(tissue-specific)
```
- **Target:** τ ≥ 0.85 (tissue-restriction score)
- **Loss:** Binary cross-entropy + focal weighting
- **Tau formula:**
  ```
  τ = Σ(1 - TPM_i / TPM_max) / (n - 1)
  ```
  where τ=1 means gene expressed in only one tissue

### Head 4: Tissue Classification
```
z_fused → Linear(128 → 46) → Softmax → P(tissue_k)
```
- **Target:** 46-class label (one per tissue)
- **Loss:** Cross-entropy

## Training Configuration

### Loss Function
```python
L_total = w_link · L_link 
        + w_expr · L_expr 
        + w_tau · L_tau 
        + w_tissue · L_tissue 
        + w_align · L_InfoNCE  [trimodal only]
```

**Default weights:**
- `w_link = 1.0`
- `w_expr = 1.0`
- `w_tau = 0.5`
- `w_tissue = 0.5`
- `w_align = 0.3`

### Optimization
- **Optimizer:** Adam
- **Learning rate:** 1e-3
- **Weight decay:** 1e-4
- **Gradient clipping:** max_norm = 1.0
- **Batch size:** 64
- **Epochs:** 40 (full), 12 (fast mode)
- **Early stopping:** patience = 8 (on validation loss)

### Mixed Precision (CUDA only)
- **AMP:** Automatic Mixed Precision (fp16/fp32 hybrid)
- Speeds up training 2-3× on modern GPUs
- Negligible accuracy loss

### Data Loading
- **DataLoader workers:** 8 (for batch collation)
- **Graph construction workers:** N_CPU - 4 (process pool, separate from DataLoader)

## Cross-Validation Strategy

### Gene-Grouped 5-Fold CV
```
Split genes (not rows) into 5 folds
For fold k:
  Train: genes in folds ≠ k
  Val:   genes in fold k
```

**Why gene-grouped?**
- Same gene appears in multiple tissues (multiple rows)
- Random row split → **data leakage** (same gene in train + test)
- Gene grouping → model generalizes to **unseen genes**

### Additional Validations
1. **Chromosome-block CV**
   - Train on all chromosomes except one
   - Test on held-out chromosome
   - Tests spatial generalization

2. **Tissue-holdout CV**
   - Train on N-1 tissues
   - Test on held-out tissue
   - Tests cross-tissue transfer

## Ablation Studies

### Variant 1: GAT-only
- Remove sequence tower (`z_seq`)
- Use only `z_struct` → heads
- Tests: "Does sequence add value beyond structure?"

### Variant 2: Sequence-only
- Remove graph tower (`z_struct`)
- Use only `z_seq` + histones (as extra features) → heads
- Tests: "Does 3D structure add value beyond sequence?"

### Variant 3: Both towers (baseline)
- Full two-tower model
- Expected: outperforms both ablations

### Variant 4: DHL Hybrid Ensemble
- Freeze `z_fused` embeddings
- Train classical ML heads:
  - Logistic Regression
  - Random Forest
  - Gradient Boosting
  - SVM
  - k-NN
- Ensemble via majority voting
- Tests: "Do embeddings capture useful structure for classical methods?"

## Model Complexity

### Parameter Counts (Approximate)
- **Sequence tower:** ~2.5M params
  - Stem conv: 4 × 15 × 128 = 7.7k
  - HyenaOperator: ~600k per block × 4 = 2.4M
- **GAT tower:** ~300k params
  - 3 layers × 4 heads × 128-dim = ~200k
  - Edge/node encoders: ~100k
- **Fusion + heads:** ~50k params
- **Total:** ~3M parameters

### Memory Footprint (16 kb promoter, batch=64)
- **Sequences:** 64 × 16384 × 4 bytes = 4 MB per batch
- **Graphs:** Variable (depends on degree, avg ~50 nodes/graph)
  - 64 graphs × 50 nodes × 10 features × 4 bytes = 128 KB
- **Activations:** ~100 MB (gradient checkpointing reduces this)

### Training Time (Single Fold, Full Mode)
- **GPU (RTX 3090):** ~6 hours (40 epochs)
- **CPU (32 cores):** ~48 hours (impractical)

## Critical Dependencies on INTERACT_DIR

### What INTERACT_DIR Provides
1. **Graph topology:** Nodes and edges for GAT
2. **Edge weights:** CHiCAGO scores → edge features + link prediction labels
3. **Tissue enumeration:** Which tissues have data
4. **Genomic loci:** Which fragments to query for histone/Hi-C data

### What Happens Without INTERACT_DIR
- **GAT tower collapses** (no graph structure)
- Model reduces to **sequence-only** variant
- **Loses 3D chromatin information** entirely
- **Cannot predict link strength** (no ground truth)

**Conclusion:** `INTERACT_DIR` is the **structural backbone** — without it, the multimodal architecture degenerates to a unimodal sequence model.

## Evaluation Metrics

### Binary Classification (Heads 1, 2, 3)
- **AUROC** — Area under ROC curve (threshold-independent)
- **AUPRC** — Area under precision-recall curve (better for imbalance)
- **F1 score** — Harmonic mean of precision/recall (at optimal threshold)
- **Calibration error** — How well predicted probabilities match true frequencies

### Multi-Class (Head 4)
- **Accuracy** — Fraction correct
- **Macro F1** — Average F1 across tissues (unweighted)
- **Confusion matrix** — Per-tissue error patterns

### Embedding Quality
- **t-SNE/UMAP visualization** — Do tissues cluster in embedding space?
- **Silhouette score** — Cluster separation in `z_fused`

## Key Innovations

1. **Long-context sequence modeling**
   - HyenaDNA reaches 16 kb in O(L log L), not O(L²) transformers

2. **3D chromatin as graph structure**
   - PCHi-C loops become learnable graph edges
   - GAT learns which contacts matter for regulation

3. **Multi-task learning**
   - 4 heads share representations → better generalization
   - Tasks are biologically related (not arbitrary)

4. **Gene-grouped CV**
   - Prevents leakage from same gene across tissues
   - Tests true generalization to unseen genes

5. **Masked missing data**
   - Missing histones → mask=0 (not zero-fill or impute)
   - Model learns to handle incomplete epigenomics

## Appendix: Graph Construction Details

### Step-by-Step Process

1. **Load loop file** (`*_merged_loop.txt` from `INTERACT_DIR`)
   - Columns: bait_chr, bait_start, bait_end, prey_chr, prey_start, prey_end, chicago_score, ...

2. **Filter loops**
   - CHiCAGO score ≥ 5.0
   - Bait fragment contains gene TSS (assembly check)
   - Gene TPM ≥ 1.0 (expressed)

3. **Build node set**
   - Anchor: bait fragment (promoter)
   - Neighbors: top-K prey fragments by CHiCAGO score
   - K capped at 10,000 (prevents memory explosion for highly-connected promoters)

4. **Extract node features**
   - Query bigWig files for histone signals at each fragment
   - Liftover hg19 → GRCh38 if needed (some ENCODE tracks are GRCh38-only)
   - Missing marks: signal=0, mask=0

5. **Extract edge features**
   - CHiCAGO score (from loop file)
   - Genomic distance: |prey_midpoint - bait_midpoint|
   - Hi-C contact: query Juicer .hic file for bait-prey bin pair

6. **Add backbone edges** (optional)
   - Connect linearly adjacent fragments (within 1 Mb)
   - Weight: fixed small value (e.g., 0.1)
   - Rationale: preserves linear genome structure

7. **Convert to PyTorch Geometric format**
   - `edge_index`: [2, num_edges] tensor (source, target node indices)
   - `x`: [num_nodes, num_features] node feature matrix
   - `edge_attr`: [num_edges, num_edge_features] edge feature matrix

8. **Cache graph**
   - Save to `cache/graphs/{tissue}_{gene}.pt`
   - Reloading is ~100× faster than rebuilding
